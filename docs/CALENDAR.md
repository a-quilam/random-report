# Календарь: собрания, закрытые аренды и исключённые подкалендари

Документ фиксирует правило по решению владельца и его конфигурацию. Источник
требований — `docs/REQUIREMENTS.md` §§3.3, 7, 13 (E01–E03); общий контракт домена —
`docs/DOMAIN.md` §7. Конфигурация задаётся **только устойчивыми ID подкалендарей**,
настоящих значений в репозитории нет (только `placeholder-*`).

## 1. Решение

Для **состоявшейся** записи (end ≤ cutoff) в **разрешённом контуре закрытых событий**
(`meeting_subcalendars`) с **точным** названием «Собрания»:

* тип `meeting`, считается **один раз**;
* в публичном календаре публикуется только **московская дата начала** и константа
  «Собрание» (`meeting_label`).

Остальные закрытые события — **только агрегаты**, с отдельной публичной категорией
**закрытой аренды** по маппингу (`rent_subcalendars`); **не каждое** закрытое
событие — аренда. Запись из **исключённого** подкалендаря (`excluded_subcalendars`)
не даёт **ни списков, ни итогов**.

Не публикуются: исходное название, ID записи, ID/серия календаря, время, URL,
описание, участники. Ни в HTML, ни в JSON, ни в CSV — у публичного DTO собрания
(`PublicMeetingDTO`) нет полей, куда это могло бы попасть.

## 2. Категории публичного календаря

| Категория | Когда | Публичная выдача |
|---|---|---|
| `open`, `open_by_registration` | публичный тип по маппингу | список + дневная сетка (как раньше) |
| `meeting` | разрешённый контур + **точное** название «Собрания» | дата начала + константа «Собрание» |
| `closed_rent` | закрытая запись из `rent_subcalendars` | только агрегат (`event_type_aggregates`) |
| `closed` | прочие закрытые | только агрегат |
| `internal_meeting`, `preparation`, `unknown` | по маппингу | только агрегат |
| *исключено* | подкалендарь в `excluded_subcalendars` | ничего: ни списка, ни счётчика |

`events.event_type_aggregates` содержит все типы, включая `meeting` и `closed_rent`;
`events.meetings` — список `{on, label}`, `events.meeting_days` — дни сетки собраний
(только для месячного периода, как и `calendar_days`). `closed_aggregate` — это
`closed + closed_rent` (собрания считаются отдельно и не удваиваются).

## 3. Консервативные правила (конфликт и неизвестность)

* **Точное совпадение, не подстрока.** «Общее собрание коммуны», «Итоги: СОБРАНИЯ!»,
  «Собрания жильцов» — **не** собрания: продвижение такой записи раскрыло бы закрытую
  дату. Такие «почти-совпадения» внутри контура помечаются для админа
  (`EventSelection.admin_flags`), но не публикуются.
* **Исключение важнее всего.** Запись в исключённом подкалендаре не попадает даже в
  контур собраний.
* **Приоритет приватности.** Запись в нескольких подкалендарях классифицируется по
  самому строгому типу; «Собрания» в чужом контуре (например, `internal_meeting`)
  остаётся своим типом.
* **Конфликт контура и аренды.** Запись одновременно в `meeting_subcalendars` и
  `rent_subcalendars` трактуется консервативно — как агрегат (`closed_rent`), без
  публичной даты; конфликт виден админу.
* **Неизвестный тип** учитывается в общем счёте и «тип не указан», авто-открытым не
  считается.

## 4. Конфигурация (только `placeholder-*` в примерах)

Источники (в порядке приоритета): строка маппинга в БД редакционного стола
(`event_type_mapping`) → приватный файл карты (`RANREPORT_EVENT_MAPPING` /
`--events`, тот же payload, что хранит стол) → переменные окружения ночного цикла
(`TEAMUP_*`). Загрузка только читает: версия стола никогда не перезаписывается
ночной сборкой. Приоритет реализован одним загрузчиком
`projection.policy.event_mapping_for`, который используют и ночной CLI, и
публичная веб-сборка.

Переменные (`randreport/domain/events.py`, `event_mapping_from_env`):

| Переменная | Значение |
|---|---|
| `TEAMUP_SUBCALENDAR_TYPES` | `id=тип` через запятую (`open|…|unknown`; `meeting`/`closed_rent` назначать нельзя) |
| `TEAMUP_PRIVATE_SUBCALENDARS` | агрегат-онли |
| `TEAMUP_EXCLUDED_SUBCALENDARS` | исключено полностью |
| `TEAMUP_MEETING_SUBCALENDARS` | разрешённый контур собраний |
| `TEAMUP_RENT_SUBCALENDARS` | закрытые аренды |
| `TEAMUP_MEETING_TITLES` | названия/слова собраний (по умолчанию «Собрания») |
| `TEAMUP_MEETING_LABEL` | публичная константа (по умолчанию «Собрание») |
| `TEAMUP_MEETING_MATCH` | `exact` (по умолчанию) или `contains` |

`TEAMUP_MEETING_MATCH=contains` — записанный владельцем вариант
(`закрытый файл правил владельца`: `source_title_contains_word` = «собрание», «собрания» при
`case_sensitive: false`): название распознаётся, если содержит одно из слов
**целым словом** и без учёта регистра. `exact` — осторожное умолчание: совпадение
целиком. Неизвестное значение режима — отказ, а не молчаливое расширение
публикации.

Пример структуры — `config/calendar_mapping.example.json`; пример переменных —
`.env.example`. Значения по умолчанию ничего не продвигают: без контура нет ни одного
собрания, без аренды нет ни одной аренды, без исключений ничего не исключается.

```

python3 -m unittest discover -s tests -t . -q          # весь suite
python3 -m randreport.web check                        # 120 страниц, 0 проблем
```

`tests/test_calendar_meetings.py` покрывает: точное совпадение против подстроки,
однократный подсчёт, раздельную категорию аренды, исключённый подкалендарь,
консервативные конфликты, отсутствие исходных деталей в JSON/HTML/CSV и синтетический
end-to-end Teamup → отчёт/календарь/JSON/CSV с явным удалением.

## 6. Замечание о сопоставлении названий

Правило записано владельцем в двух формах, и код поддерживает обе явной
конфигурацией, не угадывая:

* `exact` (**умолчание**) — совпадение целиком. Ранняя версия кода искала слово
  «собрани…» внутри любого названия (коммит «Recognize meeting words within
  longer Teamup titles»); это было неявное, менее осторожное поведение — любое
  длинное название продвигало закрытую запись на публичный календарь, поэтому
  умолчание стало точным совпадением, а разбор слова как подстроки остался для
  подсказки админу (`looks_like_meeting_title`).
* `contains` — записанный позже (в операторском файле приватных правил
  `закрытый файл правил владельца`, ревизия 4) вариант: `source_title_contains_word`
  («собрание», «собрания») при `case_sensitive: false`; включается только явно
  (`TEAMUP_MEETING_MATCH=contains`, `meeting_match` в payload файла/строки стола)
  и сравнивает слово целиком, а не подстроку.

До этого у ночного цикла не было пути применить приватные правила календаря без
записи в БД стола: загрузчик читал только `event_type_mapping`. Теперь приоритет
документирован и реализован (`projection.policy.event_mapping_for`), поэтому
staging-цикл применяет те же правила, что и бой.
