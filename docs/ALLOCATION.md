# Правила распределения подвала (owner allocation overrides)

Документ описывает **версионируемые правила владельца о том, как считается доля
подвала**, их формат, импорт оператором, обратимое исключение отдельной операции
и контракт публичного интерфейса. Реализация: `randreport/domain/allocation.py`
(модель и применение), `randreport/projection/policy.py` (загрузка),
`randreport/admin/desk.py` + `randreport/admin/app.py` (стол),
`randreport/web/hints.py` (публичное объяснение и подсказки).

## 1. Что это и чего это не делает

Правила — это **надстройка над подтверждённой картой контура**. Они не меняют
первоисточники (банковские операции, календарь, посты) и не являются локальной
денежной поправкой: они определяют, что именно попадает в *отчёт*.

Инварианты:

1. **Исключённая категория не влияет ни на один итог** — ни на общие суммы, ни
   на строки категорий: её движения вообще не доходят до агрегатов.
2. **Доля общих расходов считается по месяцам.** Доля применяется к *месячной*
   сумме целых копеек с явным округлением, поэтому год — это сумма уже
   округлённых месяцев, а не доля годового итога (`docs/TEST_RESULTS_ALLOCATION.md`).
3. **Расчётная аренда заменяет банковский платёж.** В расходы идёт согласованная
   сумма; фактический платёж публикуется **рядом** и в итоги не добавляется —
   двойного учёта нет.
4. **Расчётная аренда не экстраполируется на неизвестные периоды.** Месяц без
   реального движения аренды не получает придуманной суммы; месяц раньше
   `from_month` сохраняет настоящий платёж (закрытый отчёт назад не переписывается).
5. **Корректировки обоих знаков учитываются раздельно** и никогда не сворачиваются
   в одно число; статья без подтверждённого класса становится `unclassified` —
   выдуманного класса не появляется.
6. **Надкатегория не задваивает дочерние статьи:** от родителя остаётся только та
   часть, которую не покрывают дети.
7. **Изменение политики не переписывает остатки.** Снимки баланса
   (`account_balance_snapshots`) — отдельный источник; правка правил только
   пересчитывает проекцию отчёта и инвалидирует отметки проверки периода.
8. **Изменение политики не переписывает закрытый отчёт.** Снимок
   (`report_snapshots`) неизменяем: новая правка приходит **новой версией**.

## 2. Формат политики (JSON)

Политика — объект JSON; он хранится внутри подтверждённой карты контура под
ключом `allocation` (одна версия — один атомарный документ, та же обратимость,
что у `mapping/rollback`).

| Поле | Тип | Смысл |
| --- | --- | --- |
| `version` | строка | метка версии правил (для журнала и объяснения) |
| `confirmed` | bool | подтверждена ли политика (по умолчанию `true`) |
| `excluded_category_ids` | список ID | категории, которые не влияют ни на один итог |
| `share_rules` | объект `{ID: доля}` | доли общих расходов и ЖКУ по месяцам |
| `rent_category_ids` | список ID | категории, считающиеся арендой |
| `rent` | объект | согласованная аренда: `monthly_kopecks`, необязательный `from_month` |
| `supercategories` | объект `{родитель: [дети]}` | защита от двойного счёта |
| `corrections` | список объектов | корректировки обоих знаков |

`доля` = `{"numerator": 1, "denominator": 3, "rounding": "half_up"}`.
Допустимые `rounding`: `half_up` (по умолчанию), `half_even`, `floor`, `ceil`,
`down`. Знаменатель обязателен; неизвестное округление и float отвергаются.

`rent.from_month` = `"YYYY-MM"` или отсутствует. Отсутствие означает «любой
месяц, где есть реальная аренда».

Идентификаторы категорий — это ID источника (приватные). В **публичный** отчёт
уходит только необратимый публичный ключ категории (`k<sha256[:12]>`) и суммы.

Пример:

```json
{
  "version": "owner-alloc-2026-01",
  "excluded_category_ids": ["<ID личной категории>"],
  "share_rules": {
    "<ID ЖКУ>": {"numerator": 1, "denominator": 3, "rounding": "half_up"},
    "<ID общих расходов>": {"numerator": 1, "denominator": 3, "rounding": "half_up"}
  },
  "rent_category_ids": ["<ID аренды>"],
  "rent": {"monthly_kopecks": 9000000, "from_month": "2026-01"},
  "supercategories": {"<ID надкатегории>": ["<ID детей>"]},
  "corrections": [
    {"period": "2026-01", "amount_kopecks": 5000, "category_id": "<ID>", "reason": "уточнение"}
  ]
}
```

## 3. Импорт оператором

Импорт — это **запись новой версии**, а не правка на месте. Три пути:

1. **Стол (рекомендуется).** `POST /admin/actions/allocation/import` с полем
   `allocation_json` (форма в разделе «Настройки → Правила распределения
   подвала»). Требуются действующая сессия, CSRF-токен и совпадающий
   `Origin`/`Referer` — как у любого действия стола. Политика валидируется
   парсером отчёта, поэтому опечатка (неизвестное округление, float, не-месяц)
   отклоняется человеческой фразой и **не** попадает в отчёт.
2. **Приватный файл карты.** Тот же объект под ключом `allocation` можно положить
   в приватный файл карты контура: `RANREPORT_FINANCE_POLICY` / `--policy`.
   Загрузчик карты (`projection/policy.py`) применяет приоритет, документированный
   в `docs/DOMAIN.md` §4: свежая версия из приватной БД важнее файла.
3. **Библиотечно.** `allocation_policy_from_payload(version, payload)` —
   тот же валидатор, который использует отчёт.

Обратимость: `mapping/rollback` (вид `category`) восстанавливает прежнюю версию
как новую. Отдельного «удалить политику» нет — пустой объект делает правила
инертными.

## 4. Обратимое исключение отдельной операции (частично относящиеся категории)

Когда категория относится к подвалу **частично**, целиком её исключать нельзя.
В столе у каждой операции публичного контура есть действие **«Исключить из
отчёта»** и обратное **«Вернуть в отчёт»** (`/admin/actions/report/exclude|
report/restore`).

* требуется действующая сессия и **CSRF-токен** (проверяется общим шлюзом
  стола; без токена — `403`);
* **карточка и оба действия достижимы для любой операции подтверждённого
  контура**, а не только для тех, что попали в список: список ограничен
  `MONEY_LIMIT` (200 операций), а карточка ищет операцию **по её
  идентификатору** (`desk.money_row`) с той же проверкой счетов контура.
  Окно списка — про список, а не про доступ к одной операции
  (`docs/TEST_RESULTS_DESK_WINDOW.md`); строка с личным или карантинным счётом
  невидима и при поиске по идентификатору (`404`);
* решение хранится в `finance_report_exclusions` (миграция 7) и **обратимо**:
  строка остаётся, `restored_at`/`restored_by` фиксируют возврат;
* **первоисточник неизменен**: `finance_transactions` не меняется ни в сумме,
  ни в категории, ни в признаке удаления (локальной денежной поправки не
  существует, `docs/ADMIN.md`);
* каждое действие пишет запись в `audit_log` (`report.operation.excluded` /
  `report.operation.restored`) и инвалидирует отметки проверки периодов;
* **защита при неизвестной принадлежности:** если категория операции не
  подтверждена картой контура (или отсутствует), исключение **отклоняется**
  (`409`, фраза «принадлежность операции неизвестна…»). Исключать деньги,
  которые никто не классифицировал, нельзя.

Загрузчик отчёта складывает активные исключения в
`AllocationPolicy.excluded_transaction_ids` (`projection/policy.py:
with_stored_exclusions`), поэтому проекция, CSV и HTML видят ровно тот же набор.

## 5. Контракт публичного интерфейса (для UI)

Этот раздел фиксирует то, что обязана соблюдать переработка страниц
(`revision/visual`).

1. **Утверждённое публичное имя.** Категория показывается только под именем из
   карты контура (`ScopePolicy.category_labels`); выдумывать имя нельзя.
2. **Необязательная подсказка.** Карта может нести `category_hints` (ID → текст).
   Подсказка попадает в публичный DTO как `categories[].hint` (`null`, если её
   не утверждали). **Подсказка обязана быть доступна касанием И клавиатурой** —
   CSP сайта запрещает скрипты, поэтому hover-only подсказка не годится.
   Образец — нативный `<details><summary>` (фокусируемый и активируемый без JS),
   реализация: `randreport/web/hints.py:hint_disclosure`.
3. **Объяснение распределения.** DTO `MoneyDTO.allocation` (`AllocationDTO`)
   несёт: применена ли политика, число исключённых категорий и операций, суммы
   долей до/после, расчётную и банковскую аренду, суммы корректировок обоих
   знаков, признак неопределённой статьи, список корректировок по месяцам и
   метки. Читаемое объяснение строится из этого же DTO
   (`randreport/web/hints.py:allocation_block`), поэтому текст, JSON и CSV не
   могут разойтись.
4. **Согласованность представлений.** Один и тот же `MoneyDTO` питает JSON-API,
   CSV (allowlist-столбцы), HTML и метрики; суммы категорий в JSON, CSV и HTML
   обязаны совпадать (`docs/TEST_RESULTS_ALLOCATION.md`).
5. **Безопасность DTO.** В публичном payload нет ни ID категории, ни ID
   операции, ни счёта: только публичные ключи, суммы и счётчики. Свободный текст
   оператора (например `corrections[].reason`) в публикацию **не попадает** —
   публикуется только факт, месяц, ключ категории и сумма. Неизвестное поле и
   float отвергаются (`MoneyDTO.from_public_dict`).

## 6. Что видит посетитель

Метрики `money.metrics`: `allocation_applied`, `allocation_excluded_categories`,
`allocation_excluded_operations`, `shared_expenses_before_kopecks`,
`shared_expenses_after_kopecks`, `rent_computed_kopecks`, `rent_bank_kopecks`,
`rent_applied`, `rent_differs`, `corrections_positive_kopecks`,
`corrections_negative_kopecks`, `corrections_unclassified`, `allocation_labels`.
Метки состояния попадают и в `status_labels`, поэтому неполнота/особенность
периода видна текстом, а не цветом.

## 7. Решения и границы

* Доля применяется к **сумме за месяц** по каждой категории отдельно (правило
  задаётся на категорию). Это прямое следствие требования «месячная агрегация
  целых копеек, определённое округление, год из месяцев».
* Корректировка — отдельная запись отчёта: она попадает в свой экономический
  класс, если статья подтверждена, и остаётся `unclassified` в противном случае.
  Причина (`reason`) хранится в приватной политике и в публикацию не выводится.
* Правило доли на отсутствующую категорию ничего не делает (нет движений — нет
  строки); правило аренды на месяц без аренды не создаёт сумму.
* Выбор надкатегории/детей — решение владельца; алгоритм лишь не задваивает
  детей и не теряет «собственную» часть родителя.
