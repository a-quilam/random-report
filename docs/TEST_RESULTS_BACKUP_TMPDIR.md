# TEST RESULTS: бэкап при TMPDIR на другом разделе (t_c395208d)

Карточка: «Бэкап падает при TMPDIR на другом разделе (cross-device link)».
Фикс: `randreport/ops/backup.py` — plaintext-копия собирается в 0700 `mkdtemp`
рядом с целевым файлом (на его файловой системе), публикация остаётся
атомарным `os.replace`; каталог с копией удаляется в `finally`, включая
случай сбоя. Контракт CLI и манифест не изменились.

## Воспроизведение (RED) на коде до фикса (`e8dcf95^`)

Проверено в отрывном worktree (`git worktree add --detach <sha>`), новый тест
скопирован в него. Два режима:

1. **Реальное ядро, без патчей.** В песочнице доступна вторая файловая система:
   целевой каталог на `/dev/sda3`, `TMPDIR` перенаправлен в `mkdtemp` на
   `/dev/shm` (tmpfs, свой `st_dev`). Настоящий `rename(2)` отказывает:

   ```
   OSError: [Errno 18] Invalid cross-device link:
     '/dev/shm/rr-foreign-3f80uhk0/randreport-backup-diiq_dys/randreport.sqlite'
     -> '<root>/foreign-tmpdir-backups/rr.sqlite'
   ```

   Это точная производственная ошибка ночного бэкапа при `/tmp` на tmpfs.

2. **Шим rename(2) (для сред без второй ФС).** Если чужого устройства нет,
   тест подменяет `os.replace`: EXDEV поднимается, когда источник и цель на
   разных устройствах (по `st_dev`), либо когда источник лежит в «чужом»
   TMPDIR, который по условию стоит считать другой ФС. На коде до фикса —
   тот же `OSError: [Errno 18] Invalid cross-device link`; на коде с фиксом —
   OK.

## Что тест проверяет сверх исходной версии

Исходный тест (`e8dcf95`) поднимал EXDEV по префиксу пути — фикс, который
оставил бы staging в TMPDIR и просто заменил `os.replace` на
`shutil.move`-с-fallback, прошёл бы. Усиленная версия:

* при наличии второй ФС сценарий исполняется **настоящим ядром** без каких-либо
  патчей — TMPDIR действительно на другом устройстве;
* шим применяет семантику `rename(2)` по устройству (`st_dev`), а не по пути,
  поэтому staging в любом чужом месте (не только в TMPDIR) ловится;
* проверено, что рядом с бэкапом не остаётся каталога staging
  (`randreport-backup-*` — раньше проверка искала точечные имена и не ловила
  реальное имя каталога);
* проверено, что файл бэкапа появился.
