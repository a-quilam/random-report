# До production
Дымовая проверка архива: `python -m unittest discover -s tests -p test_history_archive.py -v`. Сборка: `python build_archive.py NEW_DIRECTORY`. Ночной цикл: `python -m randreport.ops.cli status` и `python -m randreport.ops.cli run` (секреты только из окружения). Бэкап и восстановление: `python -m randreport.ops.cli backup --db PATH --out BACKUP.sqlite.enc --encrypt` (консистентный SQLite backup API, один самодостаточный зашифрованный файл AES-256-CBC/PBKDF2 + `.manifest.json`; пароль из `RANREPORT_BACKUP_PASSPHRASE`, не в аргументах), проверка `verify-backup --backup FILE`, восстановление на чистом экземпляре `restore --backup FILE --db PATH` (без `--force` не перезаписывает существующую БД; зашифрованная копия требует пароль), retention `prune-backups --out DIR` (14 дневных + одна месячная, единственную копию не удаляет); проверяемый откат публичной проекции `python -m randreport.ops.cli rollback --publish-dir DIR (--to REL | --previous)`; сверка утверждённых сумм только для чтения `python -m randreport.ops.cli reconcile --db DB --period YYYY-MM[,YYYY...] [--publish-dir DIR]` (открывает приватную БД `mode=ro`, не мигрирует и не пишет, переиспользует замороженную доменную логику и публичный `MoneyDTO`; печатает только агрегаты и публичные ключи категорий — расхождения и причины предварительности, без операций, `transaction_id`, `account_id`; exit 1 при расхождении уровня ошибки); процедура, варианты размещения, rollout/rollback, проверка HTTPS/HSTS и единый список оставшихся доступов — docs/DEPLOYMENT.md; независимая приёмка, замеры и пробелы — docs/TEST_RESULTS_ACCEPTANCE.md. Токен TGStat для счётчиков пересылок вводится один раз вслепую: `sudo python3 scripts/enter-tgstat-token.py` (значение не попадает ни в аргументы, ни в историю; прочие настройки `/etc/randreport/randreport.env` сохраняются, `TGSTAT_CHANNEL` подхватывается из `TELEGRAM_PUBLIC_CHANNEL`). Публичный сайт: `RANREPORT_RELEASE_DIR=/var/www/randreport python -m randreport.web serve --host 127.0.0.1 --port 8099` (приватная БД не подключается: `RANREPORT_DB` командой `serve` игнорируется, страницы `/reports/*` строятся из allowlist-хранилища `reports.json` внутри релиза); статический экспорт `python -m randreport.web export --out DIR`; проверка приватности и точного времени на всех страницах `python -m randreport.web check` (0 проблем обязательно перед публикацией); снимки отчётов `python -m randreport.web seed --db PATH`; исправление периода `python -m randreport.web correct --db PATH --period YYYY-MM --field expenses --value N --reason "…"`. Редакционный стол: `RANREPORT_ADMIN_SECRET` (секрет подписи cookie, без него стол не стартует) и `TELEGRAM_OIDC_ISSUER/CLIENT_ID/REDIRECT_URI`, первый участник — `python -m randreport.admin bootstrap --db PATH --telegram-id ID` (ID заранее согласован, а не «первый вошедший»), запуск `python -m randreport.admin serve --host 127.0.0.1 --port 8098`, состав — `python -m randreport.admin member --db PATH --add/--remove ID`, отзыв сессий — `python -m randreport.admin sessions --db PATH --revoke ID`, диагностика и закрытие периода — `python -m randreport.admin diagnose|history|close|post`; контракт — docs/ADMIN.md, приёмка A01/A02/R01/H01/E2E — docs/TEST_RESULTS_ADMIN.md. Таймер-шаблон: `deploy/randreport-sync.timer` + `.service`, `OnCalendar=*-*-* 03:00:00 Europe/Moscow`, `Persistent=true`; бэкап — `deploy/randreport-backup.timer` + `.service` (04:00 МСК); публичный сайт и стол — `deploy/randreport-public.service` / `deploy/randreport-admin.service` (loopback, без публикации наружу; не-loopback только при `--allow-external-bind` и `RANREPORT_ALLOW_EXTERNAL_BIND=1`); службы не устанавливать до выбора сервера и staging. Корень webroot — только каталог результата, не репозиторий. Стол держать только на loopback до TLS. Секреты только через локальный secret store сервисного пользователя; не через чат, аргументы команд или git. До подключения production: staging, сверка scope/закрытых событий, согласование домена, проверка восстановления и ночного запуска. При утечке снять релиз и очистить публичные кэши; не откатывать на небезопасный снимок.
Боевой запуск (карточка t_1b5b08c8): постоянные службы — `deploy/randreport-{sync,getupdates,backup}.{service,timer}`, `deploy/randreport-{public,admin}.service` и отдельный TLS-терминатор `deploy/randreport-caddy.service` + `deploy/Caddyfile` (свой экземпляр Caddy, `/etc/caddy/Caddyfile` не трогается; sslip.io-адрес, сертификат Let's Encrypt). Приём новых постов без домена — `python -m randreport.ops.cli getupdates` по таймеру (сначала `getWebhookInfo`; при живом webhook опрос отказывается, webhook и очередь не сбрасываются; durable offset — после записи). Установка: пользователь `randreport`, код в `/opt/randreport` (venv без сторонних пакетов), секреты — `/etc/randreport/*.env` (0600), приватные карты — ``<закрытый каталог приватных карт>`/` (0750/0640), БД и state — `/var/lib/randreport` (0700), релизы — `/var/www/randreport`, копии — `/var/backups/randreport` (0700); `first admin` — `python -m randreport.admin bootstrap --db … --telegram-id <согласованный ID>`, вход стола — через Telegram Login widget (`TELEGRAM_AUTH_BOT_TOKEN`), OIDC — по желанию владельца. Доказательства запуска, публичный и локальный контуры — `docs/TEST_RESULTS_LAUNCH.md`.
