# Публичный сайт: SSR, API, CSV и архив версий

Документ фиксирует публичный веб-слой (`randreport/web`), его маршруты, границы
allowlist и связь с замороженным доменом (`docs/DOMAIN.md`) и слоем сбора
(`docs/INGEST.md`). Источник требований — `docs/REQUIREMENTS.md` §§3, 5, 10, 13;
матрица приёмки — `R01`, `R02`, `U01`, `E03`.

## 1. Почему SSR на стандартной библиотеке

§5 рекомендует модульный монолит и просит обосновать выбор между SSR и Astro. В
этом окружении не установлен ни один веб-фреймворк (FastAPI/Starlette/Jinja/
Astro недоступны, см. `docs/TEST_RESULTS_WEB.md`), а публичный слой обязан
запускаться и проверяться локально без внешних сервисов. Поэтому выбран
**SSR на стандартной библиотеке**: WSGI-приложение (`wsgiref`) и рендеринг
f-строками с полным HTML-экранированием, плюс статический экспорт тех же
страниц. Свойств это не отнимает:

* один процесс, один репозиторий, ноль сторонних зависимостей;
* страницы полностью формируются на сервере (SSR/static export, §3.9);
* тот же объект приложения отдаёт `/api/public/*` и CSV;
* статический экспорт даёт стабильные URL без сервера (`python -m randreport.web export`).

Переход на Jinja/Astro — механическая замена слоя `randreport/web/render.py`;
контракт (какие DTO и какие поля рендерятся) от этого не меняется.

## 2. Карта модулей

```
randreport/history.py            исторический слой: публичные агрегаты + покрытие
randreport/web/app.py            WSGI: маршруты, allowlist запроса, API, CSV, экспорт
randreport/web/render.py         SSR восьми разделов, таблицы, графики, доступность
randreport/web/release_index.py  чтение опубликованной allowlist-проекции
randreport/web/reports.py        архив версий отчётов (R01) и генерация текста
randreport/web/build.py          сборка/публикация релиза из привата через домен
randreport/web/__main__.py       CLI: serve / export / seed / correct / build / check
randreport/web/static/site.css   оформление (самиздат, WCAG AA, 360px+)
```

Публичный процесс читает **две независимые плоскости**:

1. **живая проекция** — релиз, который атомарно публикует ночной сборщик
   (`ops/publish.py`). Страница не ходит в источники и не считает финансы; она
   перечитывает `money/events/community/chronicle.json` через те же DTO-классы
   (`from_public_dict`), поэтому релиз с лишним полем физически не рендерится;
2. **исторический архив** — `history_archive` (пять опубликованных отчётов),
   плюс версии отчётов в приватной БД.

Если релиза нет, разделы не «падают» и не выдумывают данные: показывается
документированное состояние «нет данных / неполнота», а историческая часть
берётся из публичных агрегатов.

## 3. Маршруты

Восемь разделов (§3.1–3.8):

| Раздел | URL |
|---|---|
| Главная | `/` |
| Деньги | `/money` |
| Мероприятия | `/events` |
| Сообщество | `/community` |
| Поддержка | `/support` |
| Летопись | `/chronicle` |
| Архив | `/reports`, `/reports/YYYY-MM`, `/reports/YYYY`, `/reports/YYYY-MM..YYYY-MM`, `/reports/…/vN` |
| Методология | `/methodology` |

Служебное: `/static/*`, `/robots.txt`, `/healthz`.

API (§10): `GET /api/public/{overview,money,events,community,chronicle}` и
`GET /api/public/export/categories.csv`. Все они принимают только
`period`, `granularity`, `unit`; любой другой параметр, дневной или
невыровненный период отклоняются с `400` **до чтения данных**. Ошибки наружу не
содержат внутренних идентификаторов. HTML, JSON и CSV проходят один и тот же
`assert_no_leaks` (`projection/privacy.py`).

## 4. Период и состояния

* По умолчанию — текущий календарный месяц по МСК; навигация сохраняет период в
  URL; переключатель — обычная форма `GET` (работает с клавиатуры и без JS).
* Допустимы: `YYYY-MM`, `YYYY`, диапазон целых месяцев, `all`.
* Каждая страница несёт строку состояния: период, дата данных, свежесть,
  состояние проверки, полнота, источники, id выпуска. Статусы — текстом, не
  только цветом.
* Неизвестное показывается «нет данных», подтверждённое отсутствие — `0`.
  Месяц, попавший внутрь группового отчёта, помечается «частичное покрытие» и
  не делится пропорционально; год не суммируется из месяцев с пропуском.
* Сравнения (предыдущий месяц, тот же месяц год назад, год к году) выводятся
  только там, где есть цифры; иначе строка «нет данных» — неполный период не
  сравнивается с полным молча.

## 5. Мероприятия и закрытые данные (E03)

Список `public_events` и дневная сетка содержат только `open` и
`open_by_registration`. Закрытые, внутренние, подготовительные и события без
типа идут только в `event_type_aggregates` — ни названия, ни даты, ни времени,
ни точки сетки. `python -m randreport.web check` сканирует все страницы всех
периодов на `acc_/occ_/cat_/sub_/cal_/pair_/tx_`-идентификаторы, адреса
электронной почты и точное время (кроме публичного «03:00»).

## 6. Архив версий (R01)

* Для каждого опубликованного отчёта хранится **версия 1 «опубликованный»**:
  ссылка на пост, дата публикации, структурированный снимок. Оригинальный текст
  не сохраняется дословно, если его нет: пересказ не источник точных цифр.
* Исправление старого периода создаёт **новую версию** с diff и причиной
  (`python -m randreport.web correct --db … --period … --field … --value … --reason …`).
  В `report_snapshots` пара `(period_label, version)` неизменяема: перезапись
  существующей версии отклоняется, исправление возможно только новой версией.
* Публичная страница показывает, что и почему изменилось, и постоянные ссылки
  `/reports/<период>/vN` — без раскрытия транзакций.
* Текст отчёта собирается только из агрегатов снимка; `assert_text_faithful`
  доказывает, что в тексте нет числа, которого нет в снимке.

## 7. CSV (R02)

`CSV_HEADER` фиксирован (`projection/csv_export.py`): `period`, `category_key`,
`category_label`, `bucket`, `direction`, `amount_kopecks`, `amount_rub`,
`share_percent`, `unit`, `as_of`, `release_id`, `completeness`. Только целые
месяц или год и только период опубликованного релиза; нет `transaction_id`,
`account_id`, контрагентов, дневных сумм, описаний и данных календаря.

## 8. Доступность (U01)

`<main id="content">`, ссылка «Перейти к содержанию», `lang="ru"`, viewport,
подписанные таблицы (`<caption>`, `scope`), графики как inline SVG с
`role="img"` и текстовой таблицей рядом, контраст WCAG AA в `site.css`,
`:focus-visible` (фокус не удаляется), статусы текстом, мобильная вёрстка от
360px без горизонтальной прокрутки страницы (таблицы прокручиваются внутри
`.table-wrap`). Публичная часть не имеет формы входа.

## 9. Эксплуатация

```
# отдать сайт
RANREPORT_RELEASE_DIR=/var/www/randreport \
RANREPORT_DB=/var/lib/randreport/randreport.sqlite \
python3 -m randreport.web serve --host 127.0.0.1 --port 8099

# статический экспорт и проверка приватности
python3 -m randreport.web export --out /var/www/randreport-static
python3 -m randreport.web check

# засеять опубликованные снимки и записать исправление периода
python3 -m randreport.web seed --db /var/lib/randreport/randreport.sqlite
python3 -m randreport.web correct --db … --period 2025-01 --field expenses --value 74100 --reason "…"

# собрать и опубликовать релизы периодов из приватной БД
python3 -m randreport.web build --db /var/lib/randreport/randreport.sqlite \
  --release-dir /var/www/randreport --periods 2025-07,2025
```

`build` берёт оба пути — сначала из аргумента (`--db`, `--release-dir`), затем из
окружения (`RANREPORT_DB`, `RANREPORT_RELEASE_DIR`), — и **отказывает** (код 2,
одна строка в stderr, без трассировки), если хоть один из них не задан. Отказ
происходит до того, как что-либо открыто: не появляется ни БД с именем-строкой
(`None`), ни каталог релиза, а приватная БД не открывается и не мигрируется.
То же правило действует в библиотеке: `store.connect` принимает только настоящий
путь, а публикация — существующий каталог релиза. Неподдерживаемый период
(`--periods nonsense`) отказывает той же человеческой строкой, что и ночной цикл,
и тоже до чтения стора.

Корень webroot — только каталог релиза/экспорта, не репозиторий. Секретов у
публичного процесса нет. `deploy/` для сайта не требуется: тот же релиз
обслуживается любым статическим сервером или WSGI-хостом.

Разрешённое фото подвала в git не хранится: это ассет оператора. Шаг выката —
положить файл, переданный владельцем, в рабочий статический каталог службы как
`basement-photo.png` (или облегчённую версию `basement-photo.jpg`: при наличии
обоих выигрывает JPEG), права `0640`, владелец — пользователь службы. По умолчанию
это `randreport/web/static/`, тот же каталог, что задаёт `RANREPORT_STATIC_DIR`.
Главная показывает вырез с неровной кромкой, когда ассет на месте, и честную раму
с подписью, когда его нет; сам файл в allowlist-снимок GitHub не входит.

Логотип владельца (замечание 7 ветки `revision/hover-hints`) хранится в git как
**публичный** ассет `randreport/web/static/brand-logo.png` — это не фотография
подвала, а знак марки, переданный владельцем. Файл подготовлен компактно (без
ancillary-метаданных PNG: остаются только `IHDR`/`IDAT`/`IEND`) и рендерится в
`.brand` с `alt`-текстом вместо декоративной звёздочки; без файла в статическом
контуре марка возвращается к прежнему знаку `✳`, поэтому битой картинки не
возникает. Владелец двигал угол по шагам в одной и той же карточке (16° → +40° по
часовой → −80° → и, наконец, **80° по часовой от показанного −80°**, то есть ровно по
ассету), поэтому действующее значение — `transform:rotate(0deg)`, и оно стоит в
блоке оптической выключки в конце таблицы стилей: последнее слово в каскаде и есть
действующее. Там же марка сдвинута на несколько px влево (`left:-56px`, на ≤800 px
`-24px`). Поворот расширяет габаритную рамку ассета (широкий становится высоким),
поэтому размер подобран замером под поле слева от бумаги названия, а не «на глаз»:
`width:72px`, `top:-10px`, `z-index:6` выше плашки названия (на ≤800 px — `36px`,
`top:-6px`). Замер в живом браузере на 1440/390/320: рамка `1,8…83,4` и `0,3…41,1`
при начале букв на `94,5` и `47,7`, чернила марки начинаются на x = 12/6 и не
касаются кромки `.poster`, наложения на буквы нет (никаких inline `style=` под CSP
`style-src 'self'`). В том же блоке цифры подняты внутри **своей** бумаги на 4/3/3 px
(`#eventsCount`, `#subCount`, `#percent`) — вырезки и значения при этом не двигаются.

Неизвестные суммы (карточка t_1b5b08c8): пока карта категорий не согласована,
раздел «Деньги» публикует **две** обезличенные строки — приход и расход по
`key=k_unclassified` с подписью «требуют классификации» — ровно те два итога,
что уже есть в метриках. Разбивка по исходным категориям в публичный вывод не
попадает (остаётся в приватной БД и столе), поэтому неутверждённые суммы не
раскрываются; `completeness=partial`. Одновременно публикация удаляет вытесненную
ревизию того же периода (`ops.publish.prune_superseded_releases`), а выбор релиза
для периода детерминирован (`ReleaseIndex.by_period`), чтобы устаревшая более
подробная проекция не могла быть отдана.

## 10. Композиция листка (коллаж t_7961a208)

Публичная часть — не набор карточек, а **коллажный листок**: сплошная бумага
`#F0EEE6`, вырезки с неровной кромкой, тяжёлая антиква / узкая рубленая /
машинопись и три смысловые пятна (красный, жёлтый, фиолетовый). Цвета, фактуры и
бумага взяты из утверждённого макета; бумажные фактуры перенесены в
`randreport/web/static/paper_*.jpg` и подключаются через `--texture` в `site.css`.

* **Главная** — плакат: заголовок «А дорог ли РанДом?» из четырёх вырезок
  (`<h1 aria-label>`), фото подвала слева (разрешённый ассет оператора, вне git;
  без ассета — честная рама с подписью), две бумажные цифры (события текущего
  календарного месяца и подписчики с изменением), блок «ПОКРЫЛИ РАСХОДЫ» с крупным
  процентом, полосой покрытия и маленькой газетной ведомостью, блок «ЧТО ПЕРЕСЫЛАЛИ»
  и семь вырезок-разделов.
* **Семь остальных листов** — разные полосы той же газеты (`render.section_banner`
  плюс `.sheet-money`/`.sheet-events`/… в CSS): бухгалтерская полоса, афишная
  стена, типографический график, благодарности, вырезки новостей, обложки выпусков,
  читаемая колонка.
* **Состав:** `render.layout` (полотно, марка, выпуск, выходные данные внизу),
  `render.nav_cuts`, `render.home_headline`/`home_mast_head`/`home_section`/
  `home_finance`, `render.visual_photo`/`render.visual_placeholder` (фото слева либо
  запасная рама), `render.announcements_block`, `render.section_banner`,
  `render.subscriber_delta`. На главной текстовая версия графика покрытия свёрнута в
  `<details>` (легенда называет те же доли), на странице денег она раскрыта.
* **Данные:** только публичный контур. Число событий прошлого календарного месяца
  берётся из публичного выпуска того месяца (`ReleaseIndex.by_period`), история
  подписчиков — из точек соседних выпусков; изменение печатается лишь при наличии
  базы не моложе 30 суток, иначе честное «истории не хватает». Сам интервал
  называется точным числом суток (`render.subscriber_delta` возвращает длину
  промежутка, `render._delta_line` её печатает): база из публичных выпусков бывает
  много старше окна, и «за 30 дней» на 120-дневном промежутке было бы неправдой.
  Демонстрационных чисел макета (`64%`, `+124`, `36`) на сайте нет.
* **Блок «ЧТО ПЕРЕСЫЛАЛИ» и настоящие счётчики (t_ca904198):** главная читает
  секцию `announcements` публичного выпуска (`AnnouncementsDTO`): топ-3 анонсов
  по измеренным пересылкам Telegram за скользящие 30 дней (`window_from` /
  `window_to`). Подзаголовок блока всегда называет точные даты окна
  («ТОП-3 АНОНСА · 30.10—28.11.2026»), чтобы скользящий рейтинг нельзя было
  спутать с выбранным отчётным месяцем; на остальные блоки фильтр периода не
  влияет. Пересылки — главное число карточки с правильным родом
  («пересылка/пересылки/пересылок»), ссылка — на оригинальный пост t.me,
  `safe_url` отбрасывает не-http схемы. Честные состояния: релиз без секции —
  прежняя строка «Нет данных о пересылках за 30 дней»; секция с
  `fetched_at IS NULL` — «статистика ещё ни разу не получалась»; измеренное
  окно без подходящих анонсов — «анонсов с измеренными пересылками нет».
  Выдуманные посты, места и счётчики по-прежнему запрещены; карточки идут в
  том порядке, в котором их построил рейтинг (стабильная сортировка сохраняет
  детерминизм при равных пересылках).
* **Подсказки и мелкий текст (замечания 2–6 ветки `revision/hover-hints`):** у
  каждой строки ведомости **своя** подсказка — утверждённый `CategoryDTO.hint`,
  иначе короткая нейтральная фраза из подтверждённого названия, а сгруппированное
  «Прочее» перечисляет вошедшие статьи (один и тот же текст на всех строках и
  выдуманная цифра — дефекты). Подсказка — **всплывающая плашка** утверждённого
  прототипа (`.helpful:hover:after`/`.helpful:focus:after`, тёмный фон `#24201c`,
  красная тень), а не `<details>`: она появляется по наведению и по фокусу
  клавиатуры, без скрипта под CSP `default-src 'none'`. Триггер получает
  `tabindex="0"` и `data-help`; клика для подсказки нет. Рваная кромка
  `.source-sheet` и бумажная фактура переехали на псевдоэлементы `:before`/`:after`
  (тот же полигон, та же текстура), поэтому контейнер больше не обрезает плашку
  первой строки; сама строка при наведении поднимается по `z-index`, а `.trend`
  стоит выше и плашку не перекрывает. Мелкие строки «прошлый месяц» и «изменение
  подписчиков» — такие же плашки с собственным текстом; мелкий кегль увеличен
  (13/11 px), поэтому остаётся читаемым на 390/320. В шапке блока денег печатается
  короткое имя месяца, а «предварительно» и дата снимка **в плашку не пишутся**:
  владелец читает блок 340×200 как дефект механики, поэтому плашка остаётся одной
  короткой мыслью (замер ~204×93 px при ~260×90 в эталоне), а служебные факты
  доступны в раскрытии «О выпуске» на листке (`Полнота`, дата снимка) и на странице
  «Деньги» (`render.money_coverage_block`, блок состояния при `state=PARTIAL`);
  примечание — короткое «НЕ ПОКРЫТО: N ₽» из публичной метрики
  (`uncovered_kopecks`), а при неизвестном значении «НЕ ПОКРЫТО: нет данных», не
  ноль.
* **Чего нет:** счётчик пересылок канала. Ни Bot API, ни разрешённый источник
  истории постов его не отдают, поэтому «ЧТО ПЕРЕСЫЛАЛИ» печатает честное
  состояние; `render.announcements_block` готов принять настоящие записи (до трёх,
  по убыванию пересылок, карточка — только при настоящем числе пересылок и
  настоящей ссылке) — не хватает только источника. Разрешённое фото подвала
  получено и стоит на главной, когда ассет выложен (шаг выката — §9);
  художественная заглушка макета (`photo-placeholder.png`) не публикуется ни в
  одном из состояний.
